# Smart Practice in Goldberg 0.8

Smart Practice is an optional experimental activity estimate. It never identifies compositions. A single application-scoped PracticeCoordinator serializes commands into one pure PracticeEngine. The UI only observes StateFlow; SmartPracticeService owns AudioRecord independently of Activity lifetime. The service and UI share the default process.

Start/Resume is allowed only from a visible, resumed Goldberg Activity with microphone permission. The service promptly enters microphone foreground operation before initializing capture. It is START_NOT_STICKY and never opens the microphone on boot, restore, reminder delivery, binding or process recovery. Android background-start and while-in-use restrictions are respected. Activity recreation, screen lock and UI backgrounding do not stop authorized capture.

The ongoing notification exposes Pause and Stop. Pause releases capture and keeps a paused draft. Stop releases capture and freezes a review draft; it does not discard or automatically save it. A subsequent ordinary notification opens Practice. Notification permission denial can hide drawer controls; Android Active apps and in-app controls remain subject to platform behavior. Notification updates are coalesced. Capture shutdown is requested before persistence.

Audio is mono PCM16, preferred 22.05 kHz with supported fallbacks. AudioRecord uses an unprocessed source if advertised, otherwise voice-recognition capture. A 2048-sample buffer feeds bounded FFT analysis of energy, noise floor, spectral flatness, tonal concentration and attack/continuity. Sensitivity changes signal-to-noise thresholds. No speech model, stored audio or audio network request exists. The heuristic can mistake speech, recorded music or other tonal sounds for playing, and miss quiet notes/headphone-only digital pianos.

Entry confirmation is 400 ms; convincing continuation is smoothed by the detector. Same-piece gaps up to 750 ms can be bridged. Longer uncertain gaps receive no credit. Auto-pause defaults to five seconds and is configurable from 2–30 seconds. Automatically paused capture stays active to support locked-screen resume. Manual pause ends capture and requires visible user action to resume. Route changes, detectable silencing and read errors interrupt the session.

Credited duration is the existing statistics contract. Detected-active time is separate for Smart/Mixed sessions; Manual records have no detected measurement. Elapsed session time includes measured pauses. Piece intervals reconcile exactly with credited time. Each execution/resume has a generation so delayed capture callbacks and stale notification actions cannot alter another execution. No captured-evidence gap over 350 ms is credited merely because the last state was playing.

Checkpoints occur on transitions, roughly every five seconds while running, and after a 500 ms note debounce. Abrupt process loss may lose the newest uncommitted interval. Recovery is paused/interrupted (or Review), never automatically listening. Unobserved process gaps are not credited; elapsed time is labeled incomplete. Manual timing uses the same engine without microphone service. No application wake lock is used; screen-off continuity and OEM power-management behavior require device validation.

Required device validation: real soft/loud acoustic and speaker-output digital piano, rests, speech, television, fan, knocks, route changes, calls, privacy toggle, denied notifications, locked-screen pause/resume, service termination, reboot and extended thermal/battery measurements. Synthetic unit tests do not establish piano recognition accuracy.
