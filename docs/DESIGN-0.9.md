# Goldberg 0.9 architecture and compatibility

Baseline: published v0.8.0 / commit 5b22fba, version code 6, Room schema 6. Development is on feature/goldberg-0.9. The existing application ID com.opus.piano, database opus.db, migrations 1→2→3→4→5→6 and backup formats 1/schema 4–5 and 2/schema 6 are retained. No schema migration is added for this presentation release.

The implementation extends existing Compose screens, ViewModels, repositories and PracticeCoordinator. PracticeEngine remains the accounting authority; the only added practice state is a transient detector signal for honest UI visualization. The microphone foreground service, pause/resume generation guards, notes, drafts, notifications, reminders and CSV remain available. UI selection does not create a second timer. Existing unfinished sessions are reused; piece-start requests do not replace them.

AppearanceStore keeps only new presentation preferences in a separate SharedPreferences file, with asynchronous reads/writes, normalization and serialized updates. Theme, typography and existing profile-statistic preferences remain in Room. Reset Appearance changes those visual fields plus the new visual store; it never clears Room or changes identity, notes, badge dates, language, Smart preferences or reminder consent. New accent/layout/density/sort preferences are device-local and survive updates; they are not added to portable backup formats. Existing backup profile preferences remain portable.

AppCompat 1.7.1 supplies per-app language selection and older-device compatibility. MainActivity uses AppCompatActivity; localeConfig declares English/Czech, and language splitting is disabled for complete resources. A cached application Resources object supplies localized text to both screens and background notifications; it never holds an Activity. AndroidX refreshes language context at lifecycle/configuration boundaries. Standard English/Czech strings and plurals include one/few/many/other Czech categories. Fixed internal display labels retain their identifiers; user titles, notes, composer names and catalogue data are not translated or rewritten. Original third-party license/source text remains attributed in its original language.

The centralized theme defines Ivory and Nocturne, curated contrast-checked accents, typography, spacing and shared card styles. Four primary tabs retain legacy route identities where needed. Badges and history are owned by Profile. Home uses credited-time metrics and two distinct recently practiced saved pieces; per-piece summaries group multi-piece attribution by parent session. Parent Review continues to show full-session records, avoiding a misleading mixture of attributed and parent totals.

Classic Minimal Piano artwork is original vector code with shared geometry, a gentle gloss, adaptive foreground/background and monochrome mask. Night-qualified background resources provide a dark counterpart when a launcher honors configuration changes. Launchers may cache full-color icons or ignore night changes; no universal automatic switching is claimed. Minimum API 26 already supports adaptive icons, so pre-26 legacy raster assets are unnecessary. No new font or third-party audio asset was added.
